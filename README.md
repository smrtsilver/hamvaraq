# هم‌ورق (hamvaraq)

سایت مبادله‌ی رایگان کتاب: کتاب بده، ۱ امتیاز بگیر؛ با امتیاز کتاب بگیر. Django + SQLite.

## اجرا

```bash
python -m venv .venv && source .venv/bin/activate   # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
python manage.py createcachetable   # کش مشترک (محدودیت نرخ)
python manage.py migrate
python manage.py seed_basics        # استان‌ها، شهرها، دسته‌ها، تنظیمات سایت
python manage.py seed_demo          # (اختیاری، فقط DEBUG) کاربر/کتاب/مبادله‌ی نمونه؛ رمز همه demo12345
python manage.py createsuperuser
python manage.py runserver
python manage.py test
```

## داکر

```bash
cp .env.example .env
docker compose up --build            # توسعه: http://localhost:8000 با پستگرس
```

پروداکشن (`.env` با `SECRET_KEY`، `ALLOWED_HOSTS`، `CSRF_TRUSTED_ORIGINS` و `DB_PASSWORD` واقعی):

```bash
docker compose -f docker-compose.prod.yml up -d --build
```
nginx روی سرور با `deploy/hamvaraq.nginx.conf.example` جلوی پورت `127.0.0.1:8000` قرار می‌گیره.
`python manage.py createsuperuser` رو داخل کانتینر `web` اجرا کن.

## ساختار

| اپ | کار |
|---|---|
| `accounts` | کاربر (امتیاز، وضعیت، محدودیت)، نشان‌ها، ثبت‌نام/ورود/بازیابی رمز |
| `books` | کتاب، جستجو، لیست آرزو، یادداشت داخل کتاب، مسیر کتاب |
| `exchanges` | درخواست ← تأیید ← تحویل ← تأیید دوطرفه، چت (منطق در `services.py`) |
| `trust` | لایک/دیسلایک، اعتبار، گزارش و تصمیم ادمین |
| `notifications` | اعلان داخل سایت |

## قوانین امتیاز
- کاربر جدید ۱ امتیاز هدیه می‌گیرد (`WELCOME_POINTS`) و فوراً می‌تواند کتاب بگیرد؛ هر شبکه (آی‌پی) در ۳۰ روز فقط به `WELCOME_MAX_PER_IP` حساب هدیه می‌دهد (بعد از سقف، حساب با امتیاز صفر شروع می‌کند و با دادن کتاب امتیاز می‌گیرد). مبادله امتیاز نمی‌سازد، پس هدیه تنها منبع امتیاز تازه است. آی‌پی خام ذخیره نمی‌شود، فقط هش آن.
- حساب‌های هم‌شبکه‌ای که هنوز به کسی کتاب نداده‌اند نمی‌توانند از هم کتاب بگیرند.
- هنگام درخواست ۱ امتیاز نگه داشته می‌شود؛ با رد/لغو برمی‌گردد و با تکمیل مبادله خرج می‌شود.
- با تأیید یک درخواست، بقیه‌ی درخواست‌های همان کتاب رد و امتیازشان برگردانده می‌شود.
- پس از مبادله کتاب به گیرنده منتقل می‌شود (وضعیت «مبادله‌شده») و او می‌تواند دوباره آن را برای مبادله بگذارد.

## اعتماد و ایمنی
- رأی فقط بعد از مبادله‌ی کامل‌شده، یکی از هر طرف، قابل ویرایش تا ۲۴ ساعت.
- رأی‌های بین دو نفری که بیش از ۲ مبادله با هم داشته‌اند وزن نصف می‌گیرد.
- زیر ۶۰٪ با حداقل ۵ رأی: «اعتبار پایین». بدون رأی: «تازه‌وارد».
- گزارش روی کاربر/کتاب/پیام؛ هر کاربر یک‌بار برای هر مورد. ادمین در `/admin/` تصمیم و دلیل را ثبت می‌کند
  (رد، اخطار، محدودیت، مسدودسازی). ۳ گزارش تأییدشده‌ی بدقولی ← محدودیت خودکار.
- تنظیمات عددی در `HamVaraqDjangoServer/settings.py` (بخش «قوانین دامنه»).

## پخته‌سازی
- **جستجوی فارسی:** `common/text.py` (ک/ی عربی، ارقام، نیم‌فاصله) روی جستجو، لیست آرزو و هم‌سلیقه‌ها.
- **محدودیت نرخ:** `common/throttle.py`؛ پشت nginx حتماً `TRUST_PROXY_HEADERS=True` (در compose پروداکشن ست شده). برای خاموش‌کردن در توسعه: `THROTTLE_ENABLED=False`.
- **چت:** خوانده‌نشده + polling هر ۵ ثانیه (`static/js/chat.js`).
- **تاریخ جلالی:** فیلترهای `fa`, `jdate`, `jlong`, `jtime`, `ago` در همه‌ی قالب‌ها.
- **مدیریت:** `/staff/` (فقط staff) داشبورد؛ `python manage.py daily_report [--email]` برای cron، گیرنده‌ها از `ADMIN_EMAILS`.
- **سئو/PWA:** `/sitemap.xml`، `/robots.txt`، OpenGraph، JSON-LD، `/sw.js`، `/offline/`.

- **چرخه‌ی عمر مبادله:** `python manage.py expire_exchanges [--dry-run]` (روزانه): یادآوری، لغو بی‌پاسخ‌ها با برگشت امتیاز و باز کردن اختلاف خودکار. اختلاف‌ها را ادمین از `/admin/` (اکشن‌های «اختلاف: …» روی مبادله) حل می‌کند.
- **عکس‌ها:** `common/images.py` — EXIF حذف، حداکثر ۱۲۸۰ پیکسل، JPEG؛ بند‌انگشتی خودکار؛ تا ۴ عکس اضافه.
- **معرفی کتاب و اطلاعیه‌ها:** `/posts/` (نوشته‌ی کاربران، مارک‌داون امن) و `/announcements/` (رویدادهای فرهنگی با تاریخ جلالی و `.ics`)؛ تأیید در `/admin/` یا `/staff/`. یادآوری رویداد: `python manage.py announcement_reminders` (روزانه).
- **پنل مدیریت:** `/panel/` (فقط staff؛ آدرس قدیمی `/staff/` به آن می‌رود): نمای کلی، گزارش‌ها (تصمیم)، مشکلات کاربران، مبادله‌ها و حل اختلاف، کاربران (اخطار/محدودیت/مسدودسازی/امتیاز)، کتاب‌ها، معرفی‌ها، اطلاعیه‌ها، چالش‌ها، تنظیمات سایت و لاگ اقدام‌ها. ابزار پیشرفته همان `/admin/` است.
- **گزارش مشکل:** `/support/` (کاربر و مهمان؛ سقف ۵ در ساعت)؛ پاسخ مدیریت به کاربر اعلان می‌شود.
- **آمار بازدید:** `analytics/` — فقط بازدید یکتا (هر بازدیدکننده برای هر مورد یک‌بار). صفحه توکن امضاشده می‌دهد و جاوااسکریپت پس از ۴ ثانیه حضور و یک تعامل آن را برمی‌گرداند؛ ربات/مدیر/صاحب محتوا شمرده نمی‌شوند. مهمان = هش یک‌طرفه‌ی (آی‌پی + مرورگر). نمایش: `/panel/stats/` و `/accounts/stats/`.
- **بکاپ:** `python manage.py backup_db --media` (خروجی `backups/`، نگه‌داشتن `BACKUP_KEEP` تا). بازیابی Postgres: `pg_restore -c -d <db> backups/db-….dump`.
- **خطا و لاگ:** `SENTRY_DSN` اختیاری؛ لاگ‌ها در خروجی استاندارد.
- **CI:** `.github/workflows/ci.yml` (ruff، check، مهاجرت‌ها، تست روی SQLite و Postgres، داکر). توسعه: `pip install -r requirements-dev.txt && ruff check .`

وضعیت کامل و کارهای باقی‌مانده: `CHECKLIST.md`.

## نسخه‌ی ۲ (انجام‌شده)
- صفحه‌ی شهر با آمار (`/cities/`) و تازه‌رسیده‌ها.
- ثبت دسته‌ای (`/books/bulk/`) و پر کردن خودکار با شابک از Open Library (کتاب‌های فارسی ممکنه پیدا نشن؛ دستی پر کن).

- هم‌سلیقه‌ها: تو صفحه‌ی کتاب، کتاب‌های موجودِ کسایی که همین کتاب رو داشتن، دادن یا گرفتن (بعد هم‌دسته‌ها).
- نقد و ستاره: فقط گیرنده‌ی کتاب در مبادله‌ی کامل‌شده، یک نقد قابل ویرایش برای هر کتاب.
- قفسه‌ی مجازی: پروفایل کتاب‌ها رو روی قفسه نشون می‌ده (به‌جز رزروها).
- چالش‌های فصلی: از `/admin/` چالش بساز (نوع، هدف، بازه)؛ پیشرفت از مبادله‌های کامل‌شده حساب می‌شه و رسیدن به هدف نشان می‌ده.

- نقطه‌ی تحویل پیشنهادی: ادمین «نقاط تحویل» (مترو، کافه…) را در `/admin/` تعریف می‌کند؛ یک طرف پیشنهاد می‌دهد، طرف مقابل تأیید می‌کند و هر دو در چت ثبت می‌شود.
- کارت اشتراک‌گذاری استوری: `/books/<id>/card.png` (۱۰۸۰×۱۹۲۰، فونت وزیرمتن). آدرس چاپ‌شده از `SITE_URL`.

نسخه‌ی ۲ کامل است.
