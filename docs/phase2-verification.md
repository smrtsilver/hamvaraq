# فاز ۲ — معامله و اعتماد (بخش بدون نیاز به تصمیم)

## مهاجرت و بک‌فیل
```bash
./update.sh prod     # accounts 0005 (دفتر امتیاز + «موجودی اولیه» برای همه‌ی کاربرها در همان مهاجرت) و exchanges 0007/0008
docker compose -f docker-compose.prod.yml exec -T web python manage.py check_points_ledger        # باید «هم‌خوانه»
```
- مهاجرت برای هر کاربر یک ردیف `opening` با delta = امتیاز فعلی می‌سازد؛ از آن لحظه مجموع دفتر = `User.points`.
- ناهمخوانی (مثلاً دست‌کاری مستقیم دیتابیس): `check_points_ledger` خروجی غیرصفر می‌دهد؛ `--fix` ردیف «اصلاح دفتر» می‌زند. در `daily_report` هم شمارش ناهمخوان‌ها هست.

## چه چیزی اضافه شد
| مورد | رفتار |
|---|---|
| دفتر امتیاز | `common.points.apply()` تنها راه تغییر امتیاز (اتمیک با `F`): هدیه‌ی ثبت‌نام، نگه‌داشتن/برگشت امتیاز درخواست، پاداش مبادله، تغییر مدیر (پنل و فرم ادمین)؛ صفحه‌ی `/accounts/points/` |
| لغو | `cancelled_by`، `cancel_reason`، `cancelled_at`؛ فرم لغو دلیل اختیاری دارد؛ لغو سیستمی `cancelled_by=None` و دلیل «سیستم: …»؛ پنل کاربر لغوها را نشان می‌دهد؛ ۳ لغو بعد از تأیید در ۳۰ روز (`CANCEL_AFTER_ACCEPT_FLAG`) فقط **سرنخ مشکوک** در داشبورد است |
| relist | ۷ روز (`RELIST_REMIND_DAYS`) بعد از تحویل، اگر کتاب هنوز «مبادله‌شده» و دست گیرنده است، یک‌بار اعلان (+پوش) با لینک؛ در `expire_exchanges` |
| ارسال پستی | فقط صاحب کتاب، فقط مبادله‌ی تأییدشده‌ی بدون اختلاف: کد رهگیری ۸–۳۰ حرف/عدد (ارقام فارسی ok)؛ گیرنده اعلان می‌گیرد؛ تأیید تحویل مثل قبل |

## هنوز منتظر تصمیم شما (فاز ۲)
- **OTP/موبایل و هدیه‌ی بعد از تأیید شماره**: ارائه‌دهنده‌ی SMS و بودجه؟
- **جریمه‌ی لغو بعد از تأیید روی امتیاز اعتماد/امتیاز**: سیاست؟ (الان فقط ثبت و سرنخ؛ هیچ جریمه‌ی خودکاری اعمال نمی‌شود)
- **کانال‌های اعلان بیرونی** (بله/تلگرام/ایتا/SMS): کانال اصلی؟
- هزینه‌ی پست و اینکه چه کسی می‌پردازد (الان بین دو نفر توافقی است و مدل نمی‌شود).

## برگشت
`git checkout <قبلی> && ./update.sh prod`؛ مهاجرت‌ها برگشت‌پذیرند: `migrate exchanges 0006`، `migrate accounts 0004` (دفتر امتیاز حذف می‌شود ولی `User.points` سالم می‌ماند).
